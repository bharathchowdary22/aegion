# ADR-009: Render for Backend Deployment

## Decision
We plan to deploy the FastAPI backend services and PostgreSQL database to Render.

## Reason
Render provides a highly simplified, Git-backed PaaS experience similar to Heroku, but with modern features like private networks and native Docker support. It reduces the DevOps burden required to manage Kubernetes or raw AWS EC2/ECS instances during the early phases of the project.

## Alternatives considered
- **Heroku**: Historically popular, but has removed free tiers and is generally considered more expensive for equivalent compute compared to Render.
- **AWS ECS/EKS**: Provides maximum control, but requires significant DevOps investment (Terraform, CI/CD pipelines, networking) which distracts from core product development in Phase 0/1.

## Consequences
- Less granular control over the underlying infrastructure compared to raw AWS.
- We must ensure our architecture remains portable (via Docker and environment variables) to allow migration to AWS or GCP if we outgrow Render.
