# ADR-006: Redis for Caching and Temporary State

## Decision
We will use Redis as our in-memory data store for caching, message brokering, and managing temporary state.

## Reason
Redis is extremely fast and well-suited for managing ephemeral data such as user sessions, rate limiting counters, WebSocket/SSE connection states, and caching frequently accessed data. It also serves as a robust message broker for background tasks (e.g., via Celery or ARQ).

## Alternatives considered
- **In-memory dictionary (Python)**: Does not scale across multiple backend workers or instances.
- **Memcached**: Lacks advanced data structures (lists, sets, streams) that Redis provides, which are highly useful for building AI memory and chat streaming features.

## Consequences
- Adds another service to our infrastructure stack.
- Requires managing Redis memory limits and eviction policies.
