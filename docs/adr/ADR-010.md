# ADR-010: OpenAI Responses API for Future AI Integration

## Decision
We plan to use the OpenAI API and its new Responses API (where applicable) as the initial foundation for our AI integrations.

## Reason
OpenAI provides the most mature, capable, and reliable models currently available. The API ecosystem (including tool calling and structured outputs) is highly stable, making it the best choice for rapidly developing the core reasoning and generative features of Aegion.

## Alternatives considered
- **Anthropic Claude (Bedrock/API)**: Excellent models, particularly for coding, but we will start with OpenAI due to broader ecosystem tooling support (e.g., standard OpenAI client interfaces). We intend to implement a Model Router later to support Claude.
- **Local/Open Source Models (Ollama, vLLM)**: Great for privacy and cost, but currently lack the reasoning capabilities of frontier models for complex multi-agent cybersecurity tasks.

## Consequences
- Vendor lock-in risk. We mitigate this by abstracting the AI calls behind an internal `AI Orchestrator` module rather than coupling our business logic directly to the OpenAI client.
- Data privacy considerations when sending sensitive cybersecurity data to a third-party API (must review enterprise data agreements).
